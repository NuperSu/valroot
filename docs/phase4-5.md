# Storage and raw provenance

SQLite stores raw records under a canonical source namespace, native identity and network, independently of providers. Each distinct UTF-8 payload is keyed by its SHA-256 checksum; observations retain source identity, retrieval time and context. Duplicate observations are idempotent, conflicting metadata is rejected, and revisions remain available. A namespace must only be shared between providers that use comparable native identities. Payload checksums are validated on ingest.

The common SQL port provides serialized transactions, rollback on exceptions, and foreign-key enforcement on store initialization. A new database gets the raw, activity and ownership schemas in one transaction; a database at any other schema version than the current one is refused. Opening checks SQLite integrity and foreign keys. Every platform uses the same SQLite, bundled with the app (`BundledSqliteDatabase` on androidx.sqlite's bundled driver): write-ahead logging with full synchronization (a committed transaction survives power loss), a 30-second wait for another connection's lock, and transactions that take the write lock when they begin. Retrieval timestamps are validated as UTC instants. Records are durable user data, and this database is not encrypted: protect local files and backups using platform measures. `BundledSqliteDatabase.snapshot` uses SQLite VACUUM INTO to create a consistent snapshot in a new destination file while the database remains open; copying an open database file is not a supported backup procedure.

Ownership snapshots persist owners, account hierarchy, tracking targets, tags and portfolio memberships atomically. Portable backup/export is implemented (`BackupService`, [backup format](backup-format.md)); the live database is still plaintext. The raw ingestion interface does not itself manage checkpoints; ingestion can be composed into a caller-owned transaction with `ingestInTransaction`.
