# Code review — 2026-11-14

Line references are as of commit 87865d5 and may drift.

This is a review report, not a certification. It does not close any roadmap gate.

## Method

Six parallel read-only audits (accounting/ledger, Bitcoin/sync, exchanges, storage/EVM/market, shared UI, Android/desktop/build), followed by a direct read of each high-severity and most medium-severity claims. No build or test was run for the review itself.

Conventions as in [README.md](README.md): **[V]** confirmed by reading the cited source; **[R]** reported by an audit pass and plausible, not independently confirmed. Severity: **P0** data loss or wrong money; **P1** wrong results in realistic use; **P2** edge case or misleading; **P3** cleanup and hardening.

Paths are relative to `core/src/commonMain/kotlin/io/valroot/core/` unless stated.

## P0 / P1 — fix first

### R14-1 · P0 · [V] — FIFO replays non-Bitcoin actions by source prefix, not time

- Where: `application/AccountingService.kt:258-264`.
- When every Bitcoin activity is chain-verified, the comparator's first key is `chainOrder[id] ?: ""`. All non-Bitcoin actions share `""` and fall through to `order` (the ordering key, whose prefix is the source), so `binance:` sorts before `evm-chain:` regardless of time. `mixed` only looks at Bitcoin assets, so nothing is flagged uncertain.
- Scenario: EVM wallet buys ETH in January; Binance buys ETH in March and withdraws it to the wallet in April; the wallet sells in May. The March lot is consumed first.

### R14-2 · not a defect · [V] — Third-asset fee disposed with zero proceeds

- Where: `application/TransactionDraft.kt:197-200`.
- Reported as a P0: the fee disposal uses `zero()` proceeds although `feeUnitPrice` is required. This is the documented policy (`docs/frontend-rewrite.md`: "fees are separate expense disposals at zero proceeds"); `feeUnitPrice` is evidence of the fee's worth, shown in the coin timeline (`sharedUi/…/TransactionTimeline.kt:205`). No change.

### R14-3 · P1 · [V] — Pending Bitcoin transactions outside the 50-entry mempool page are reversed

- Where: `bitcoin/BitcoinScanStage.kt:463-476`; `bitcoin/Esplora.kt:95`.
- Reconciliation reverses every non-reversed Bitcoin activity absent from the scan. An address whose mempool exceeds 50 entries shows only the newest 50; an older still-pending transaction seen earlier is saved as REVERSED.

### R14-4 · P1 · [V] — Any non-stop exchange error ends a history stream as complete

- Where: `exchange/ExchangeConnector.kt:141-146`.
- The catch exists for "window older than retained" refusals but accepts every `ExchangeApiException` that is not rate-limit, invalid key, clock skew or server error. A malformed-parameter error (or Binance `success:false`, mapped to code −1) permanently marks the stream complete with no note.

### R14-5 · P1 · [V] — Android periodic sync fails in the background on Android 12+

- Where: `androidApp/src/main/kotlin/io/valroot/android/RefreshWorker.kt:31`.
- `setForegroundAsync(...).get()` runs unconditionally. From the background Android throws `ForegroundServiceStartNotAllowedException`, so the worker fails before syncing and records no status.

## Structure

- `AccountingService.report()` (258 lines) and `BitcoinService.refreshScan` (325 lines) mix several policies; most accounting findings sit inside `report()`.
- Exchange transports duplicate pacing, blocking and response reading and have drifted (4 vs 16 MiB caps, 401/403 handling).
- Duplicated logic: Bitcoin graph rules (`BitcoinTransactionGraph` vs `BitcoinStagedGraph`); `ClassifiedActivityProjection` re-implements link resolution without the cross-asset scale.
- Dead or test-only code: `BitcoinScanReconciler`, the legacy snapshot writer in `BitcoinGraphRepository`, `OverlayRepository.replayClassificationsBatched`, `HoldingsRepository.reconcile`.
- Financial aggregation (FIFO performance, location sums, FRESH price rule) lives in `sharedUi`.
- `PortfolioApplication` construction writes to the database; notification checks run a full snapshot to read valuations.
- `ValrootApp.kt` is at 759 of 800 lines.
- CI never runs `ReliabilityInstrumentation`; `androidApp` has no JVM tests.

## Fix status

Verified with `:core:jvmTest`, `:androidApp:compileDebugKotlin`, `:androidApp:lintDebug` and `ktlintCheck`. Nothing was run on an Android device or emulator.

- **R14-1 fixed.** `FifoAccounting.chainOrder` places every action by time and refills the Bitcoin slots in chain order, so other sources keep their time order. Regression: `FifoTest.chainOrderKeepsTimeOrderForActionsWithoutChainKeys`.
- **R14-2 not a defect** (documented fee policy).
- **R14-3 fixed.** Reconciliation no longer reverses a missing PENDING activity of an account whose address has more unconfirmed transactions than Esplora lists. Regression: `BitcoinChainAcceptanceTest.pendingTransactionsNoLongerListedInABusyMempoolAreNotReversed` (fails without the fix).
- **R14-4 fixed.** A refused older window ends a stream only when the newest window already read still reads (a retention end, rechecked monthly). Otherwise, or for answers without a code, the stream stays incomplete with an account note and is retried after a day, a week, then monthly. Streams completed under the old rule are checked once. Exchange accounts show whether history is complete, still being read or partly refused. Opening amounts of complete accounts can count at their market value (opt-in, labelled as estimated). See `docs/exchanges.md` (History ends, Opening balances).
- **R14-5 fixed, not device-verified.** The periodic worker continues as ordinary work when Android refuses the foreground request.
- **R14-8 fixed** alongside R14-3: each address summary is requested once during verification.
